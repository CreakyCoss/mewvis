# 应用工坊

应用工坊位于 `apps/applications/builtins/app-workshop`，以普通内置应用接入 Mewvis。小应用先创建项目，再进入编辑页修改或让 AI 生成源码；构建完成后，用户保存版本并在应用工坊中使用。

## 页面与流程

首页应用列表按项目创建时间从早到晚排序，新建项目追加到末尾，编辑或保存不会改变列表位置。

首页采用连续分栏：左侧为 320 px 的灰色小应用列表，顶部并排放置「应用工坊」和「新建小应用」；右侧顶部为所选应用介绍与操作带，下方界面预览直接铺满剩余区域，不再套独立圆角卡片。列表将名称与状态放在同一行，状态使用 13 px 字号、24 px 高的浅色标签，固定在右侧 76 px 的列中；长名称单行省略，说明独占下一行，各行状态不随名称长度错位。列表不再提供更多菜单；「运行」使用紫色主按钮，「删除」与「继续开发」使用统一尺寸、圆角和描边，保留红色文字与图标，放在「继续开发」旁边，仍先打开删除确认弹窗。所选应用的状态与更新时间同样并入名称行，操作按钮在介绍区垂直居中；较窄窗口将操作组移到介绍下方，手机布局使用可横向滚动的应用列表。首页不显示「我的小应用」、预览标题或底部说明。没有保存版本的项目显示「待生成」。

首页界面预览可以滚动查看完整内容，但不接受小应用的操作，也不会写入预览状态。运行页与继续开发页共用 `ApplicationHeader` 组件，两页都优先通过公共 SDK 的 `header` 接口显示导航，成功接入后移除页面内的 header。macOS 将导航组放在覆盖式 40 px 顶栏的最右侧，距离右边缘 12 px；Windows/Linux 保留原生标题栏，将导航组放在内容区内的 40 px 导航行左侧，Web 采用相同布局，首页不预留这行导航。导航组使用 32 px 高、8 px 圆角、浅灰背景与轻边框；组内依次显示返回工坊按钮、短分隔线与应用名，文字为 12 px，长名称省略，返回按钮悬停时显示内缩的背景。应用名或按钮禁用状态变化时直接更新顶栏，仅在返回首页或离开应用时释放。旧宿主及独立开发预览不支持该接口时保留页面内的 40 px header。点击「运行」后，已保存版本占满导航下方的内容区域；运行页不提供开发切换或继续开发入口。修改应用需先返回首页，再进入开发页。

编辑页以 AI 应用创作为主：左侧是占满可用空间的应用预览，右侧是 AI 助手会话。创作区采用单行紧凑 header，将「AI 应用创作」与说明并排放置；用户消息以浅灰气泡靠右，助手回复靠左，均不显示头像。输入框沿用故事应用 AI 助手的样式：12 px 圆角、柔和阴影、紧凑多行输入，底部仅提供模型下拉、权限图标和圆形发送／停止按钮。输入区仍提供需求建议，只填入输入区，由用户发送。AI 完成生成后刷新预览，预览可直接操作或展开。

预览区使用与助手 header 等高的 54 px 固定 header，始终位于左侧代码与预览内容上方，左侧只显示「应用预览」标题，右侧集中放置版本入口、更新预览、保存版本和视图选择。预览 header 不再显示保存状态文字或状态点；内容状态只在版本管理弹窗中展示。右侧按「V1 下拉、更新预览图标、保存版本图标」排列，共享浅灰背景和轻边框，不设组内分隔线；操作组与视图组共用 32 px 高、6 px 圆角及 2 px 内边距，内部图标按钮为 28 × 26 px、4 px 圆角及 16 px 图标。悬停时白色背景内缩在组容器中，只有悬停提示和可访问名称显示完整操作文案。版本保持紧挨更新预览，缩写为「V1」等。三种视图仍使用独立的 32 px 高分段按钮组，只有当前视图以浅紫色突出。更新预览会保存源码并重新构建当前内容，代码区域和预览空态不再提供重复的更新按钮；展开／收起预览按钮浮动在预览容器右上角，随状态切换相反图标。

视图选择提供「同时显示」「仅代码」「仅预览」三种方式，默认仅预览。同时显示时，文件树与代码在左、应用预览在右，两者占满内容区高度，右侧 AI 助手保持独立；分隔条支持拖动或键盘调整宽度。代码左侧继续保留文件树，默认宽度由 144 px 增至 180 px，通过编辑器工具栏的侧栏方向图标折叠或展开，展开时显示向左收起图标，折叠时显示向右展开图标；项目文件标题旁使用简洁加号新增文件。文件树右侧和 AI 助手左侧新增 6 px 分隔条，支持拖动、方向键调整宽度及双击恢复默认值；调节结果在切换视图或放大再收起预览时保留。文件树宽度为 140–360 px，AI 助手宽度为 320–640 px，上限随可用空间收紧，避免挤占代码与工作区。代码区操作图标统一为 16 px、1.75 px 描边，按钮统一为 30 px、6 px 圆角，并使用中性色与悬停反馈。代码区较窄时，文件树浮在编辑器左侧，仍可拖动右侧边缘调宽。窄屏同时显示时，代码和预览按上下排列，分别保留足够高度；AI 助手继续位于下方，不显示横向拖拽入口。仍可新建、编辑、删除源码文件，查看错误位置、更新预览、保存版本和恢复历史版本；切换视图保留尚未保存的编辑内容和预览运行状态。切换文件、离开编辑页、发送需求前会保存当前源码；发生并发修改冲突时保留本地内容，由用户重新读取或处理。开发页不提供「开发／使用」切换。

版本操作集中在预览 header 的当前版本入口和「保存版本」图标按钮。内容与当前版本有差异时保存按钮可用，内容一致时禁用；尚未保存版本时可保存首个版本，AI 生成或其他操作进行中暂时禁用。点击保存会保存当前源码、重新构建并刷新预览，构建成功后保存版本；构建失败保留修改和诊断，不覆盖保存版本。用户无需先手动更新预览，保存成功后按钮恢复禁用。创建新版本也会自动更新预览。版本管理采用紧凑弹窗：当前版本与内容状态并排展示，状态保留颜色点，去掉前面的「·」分隔符；版本列表使用连续行和细分隔线，当前行以浅紫底色、左侧标记和「当前版本」标签突出。用户可见的文案统一使用「内容有修改」「内容已同步」「当前内容」，不称为草稿。每个项目内部始终只有一份开发草稿，编辑、构建和预览都使用它。版本面板提供版本切换、「还原到当前版本」及「创建新版本」。切换、还原和创建版本都使用独立的小确认弹窗，版本列表始终保留在后方，不切换到二级页面；取消、关闭或按 Esc 只关闭确认框，保留列表滚动位置并恢复发起操作的按钮焦点。创建成功后关闭确认框、自动更新列表并选中新版本，创建失败则保留确认框供重试。内容与当前版本一致时还原按钮禁用，切换其他版本仍需确认；有未保存到版本的修改时，切换和还原的确认框提示将丢弃修改，再用目标版本覆盖当前内容。尚未保存过版本时不提供还原操作。操作期间在按钮中显示进度，操作结果使用自动消失的通知，不再插入编辑页文字提示条。通知复用公共设计系统，原生对话框内的通知同样可见；编译诊断和运行错误保留在对应预览区域。

运行版本与开发草稿分别维护。编辑或构建失败不会替换正在使用的版本。首次「保存版本」创建版本 1，之后保存会覆盖当前选中版本的内容，保持版本 UUID 和列表位置不变；只有点击「创建新版本」才增加版本并切换到新版本。切换版本会替换草稿源码和正在使用的版本，之后保存会覆盖所选版本；还原到当前版本只替换草稿，不新增或覆盖保存版本。未保存状态按全部源码的实际内容（包括新增、删除文件）与当前版本比较，自动保存源码和构建不会清除该状态；将内容改回当前版本时也不会因 revision 增加而误判为未保存。编辑器中尚未写入文件的修改也参与比较，确认切换或还原后直接丢弃，不先保存源码。

## 接入与边界

应用声明 `application-workspaces`、`application-data`、`workspace-files`、`chat` 和 `embedded-views` 权限。工坊使用已有公共 SDK 管理工作区、聊天与子视图，不引入专用宿主业务命令。

每个小应用使用独立、专属登记的工作区，源码保存在真实的 `source/` 项目目录中。`package.json`、`tsconfig.json` 属于小应用源码，与组件、样式一起编辑和纳入历史版本。工作区结构如下：

```text
<workspace>/
├── source/
│   ├── package.json
│   ├── tsconfig.json
│   ├── .gitignore
│   ├── src/
│   │   ├── main.tsx
│   │   ├── App.tsx
│   │   └── styles.css
│   └── public/
├── .workshop/
│   ├── project.json
│   └── builds/
│       ├── <project-uuid>.json  # 草稿构建，重复构建覆盖
│       └── <version-uuid>.json  # 当前版本重复保存覆盖，创建新版本才新增
├── .mewvis/workspace.json
└── .mewvis/chats/
```

`.workshop/project.json` 使用 format 2，仅保存项目说明、revision、源码摘要和版本索引，不再保存工作源码。构建产物及源码快照保存在 `.workshop/builds`。每次成功构建覆盖固定的 `<project-uuid>.json` 草稿文件；「保存版本」将当前草稿复制到当前版本的 `<version-uuid>.json`，首次保存才分配版本 UUID。「创建新版本」会分配新的版本 UUID 并加入版本列表，即使内容相同也会创建。保存不再根据源码或产物是否变化自动决定新增版本。历史恢复会将快照写回真实源码目录，并复制到固定草稿文件中供预览，后续构建仍覆盖该草稿文件。版本列表时间表示创建时间，覆盖保存更新该版本的 sourceRevision 和产物，其他版本保留。聊天继续由宿主保存在 `.mewvis/chats`，工坊不移动或改写该目录。

工坊工具的文件路径均相对于 `source/`，例如 `src/App.tsx`，不能访问 `.workshop` 或聊天目录。源码提交使用 revision 检查、文件锁和逐文件原子替换；多文件修改通过 `.workshop/source-transaction.json` 记录事务，进程中断后继续恢复。宿主进程退出遗留的锁只在确认原进程不存在后回收。读取拒绝符号链接、硬链接、越界路径及超过限制的文件；`source/.git`、`node_modules` 和 `dist` 不作为源码读取或随版本恢复删除。删除项目只允许当前应用登记的专属工作区。

在外部编辑器修改 `source/` 后，下一次读取会更新 revision 并清除过期的草稿构建，已保存的运行版本保持原样。过期保存及事务恢复遇到外部冲突会保留现有文件并报错；中断事务存在冲突时，需先合并相关文件，使其与事务的修改前或修改后内容一致，再重新读取项目。

AI 会话通过公共 `Chat` 组件与 `ApplicationChatSession` 接入，每个项目拥有独立的 `workshop-developer` 场景。助手标题右侧提供新建会话和会话历史按钮，历史仅列出当前小应用的创作会话，可点击恢复；再次进入编辑页会恢复上次选中的会话。切换前保存当前会话，AI 创作或会话切换过程中禁用这两个按钮。开发助手仅能调用以下工具：

- `workshop_read_project`、`workshop_read_file`：读取当前项目与源码。
- `workshop_write_file`、`workshop_delete_file`：使用最新 revision 修改源码。
- `workshop_build`：编译并返回诊断。

创建、版本保存、新版本创建、历史恢复及删除项目由界面操作。开发会话不授予安装依赖、进程执行或联网能力。

编译器读取 `source/` 后仅在内存中用 TypeScript 转译并解析导入关系。`package.json` 的脚本不会执行，依赖声明不能扩展工坊的依赖白名单；`tsconfig.json` 用于项目与编辑器配置，工坊仍使用固定的浏览器转译选项，并拒绝外部 `extends` 和编译插件。生成代码不会在 Node 宿主中执行；浏览器产物仅在 `sandbox="allow-scripts"`、不透明源、严格 CSP 的子视图中运行。应用工坊为子视图提供 `state.read` 和 `state.write` 两个方法，状态按项目及 preview／live 范围隔离。子视图不能读取其他项目、获取工坊的宿主桥或直接调用系统工具。

## 当前支持范围

支持项目内 JS、JSX、TS、TSX、CSS、JSON 模块，以及 React、`react/jsx-runtime`、`react-dom/client`、`@mewvis/app-sdk/views`。入口为 `source/src/main.tsx`；源码目录还可保存 Markdown、文本和 HTML 文档，`public/` 为预留资源目录，目前不作为静态资源服务器发布。构建产物附带 Mewvis 公共主题令牌；宿主主题更新仍通过视图 SDK 传递。

暂不支持任意 npm 依赖、Node 后端、外部资源或网络。CSS 的 `@import` 和 `url()` 会产生构建诊断。每个项目最多 64 个文件、1 MiB 源码，每个文件最多 128 KiB；每个构建最多 3 MiB，保存版本最多 100 个。

## 内置小应用

内置小应用由工坊自己的 `mini-apps/registry.json` 管理，随工坊一起打包，不需要修改宿主或顶层应用登记。当前内置「猫猫收纳所」；开发预览的 `--seed` 仍是独立测试数据。

「猫猫收纳所」包含「纸箱小屋」的 8 个关卡，逐关解锁，支持重玩和继续未完成的摆放；后续两个章节显示为筹备中。猫猫可拖入纸箱，也可选中后点击格子放置；再次点击猫猫或使用旋转按钮转身，支持撤销、重来、求解提示及冲突摆放修复。键盘可用方向键调整位置，`R` 旋转、`Enter` 放置、`Escape` 取消选择、`Delete` 放回待安置区、`Ctrl/Cmd+Z` 撤销。

关卡定义位于 `mini-apps/cat-packing/source/src/levels.ts`，纯规则与提示求解器位于 `engine.ts`；新增关卡应通过可解性检查。进度经 SDK `state.read` / `state.write` 保存到小应用自己的 `cat-packing-v1` 状态键，包含通关记录与各关摆放。插画使用随源码打包的 WebP，不依赖外部网络；`scripts/embed-assets.mjs` 负责从模板目录的素材生成内嵌资源和 Lucide 图标。

添加一个模板时，将完整源码放入以下目录，再把目录名加入 `applications` 数组。只有显式登记的目录参与打包，数组顺序决定首次安装顺序。

```text
app-workshop/mini-apps/
├── registry.json                 # { "applications": ["my-tool"] }
└── my-tool/
    ├── manifest.json
    └── source/
        ├── package.json
        ├── tsconfig.json
        └── src/
            ├── main.tsx
            ├── App.tsx
            └── styles.css
```

`manifest.json` 示例：

```json
{
  "name": "我的工具",
  "description": "这个小应用的用途。",
  "version": 1
}
```

目录名是模板的稳定 ID，使用小写字母开头的小写字母、数字和连字符，最多 64 字符；名称最多 80 字符，说明最多 500 字符，模板版本是从 1 开始的正整数。可以复制已有工坊项目的完整 `source/` 作为模板；不要复制 `.workshop`、聊天记录或运行数据。源码、依赖与资源限制与普通项目相同。

`prepare:runtime` 使用工坊的源码读取器和编译器校验全部登记模板，生成包含源码的 `main/host/generated/builtins.ts`，随后由正常应用打包流程嵌入 Node 包。安装后的应用不依赖仓库目录，也不执行模板的包脚本。重复目录、无效清单、缺失文件、符号链接或编译错误会阻止构建。

首页先调用 `workshop_list_builtins` 获取模板目录，再调用 `workshop_initialize_builtins` 初始化，最后加载项目列表。初始化是独立的写操作，`workshop_list_projects` 保持原有语义。每个新模板创建一个专属工作区，直接保存可运行的 V1；名称相同的用户项目不会被替换。模板创建与初始化工具仅由界面使用，不加入 AI 创作工具集合。

安装记录保存在工坊默认工作区的 `.workshop/builtins.json`，按模板 ID 保存目录预约、项目 ID、模板版本及安装状态。初始化使用文件锁，重复打开和并发调用不会重复创建；中断后复用已预约的目录，外部改动冲突会保留源码并报告错误。单个模板失败不会阻止其他模板安装和已有项目显示，首页「重新加载」可重试。默认工作区的安装记录应随项目一同备份。

用户删除项目后保留删除记录，重启或升级不会自动重新安装。已经安装的模板在升级时也不会覆盖用户源码、版本、聊天或运行数据。清单非空时，「新建小应用」提供模板选择，通过 `workshop_create_from_builtin` 添加最新模板的新副本；这也是删除后重新添加或采用新版模板的入口。每个副本使用新的项目 ID，数据独立；模板版本与用户项目的保存版本分别管理。移除清单条目只影响后续分发，已有项目仍可继续使用。

## 开发与验证

```sh
pnpm --filter @mewvis/app-workshop check
pnpm --filter @mewvis/app-workshop test
pnpm --filter @mewvis/app-workshop dev -- --seed
```
