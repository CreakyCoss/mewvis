# 游戏沙盘

游戏沙盘位于 `apps/applications/builtins/gameplay-lab`，将核心策略定义、数值编辑、抽象试玩与实验比较组织为一个独立应用。它先验证模型，再为后续载体设计保留版本依据。

## 首版工作流程

每次打开应用先进入项目库，没有用户项目时显示空态。内置“多路径发展”和“组合计分”作为策略模板保留，用户填写项目名称、选择模板和父目录后，创建独立项目文件夹并进入工作台；不会自动生成示例项目。项目库支持重新打开已有目录。在模型工作台添加状态、能力、行动和目标；点击图中定义，在右侧修改数值和说明，高级规则提供成本、效果和前置能力编辑。关系图从实际引用生成，定义列表使用同一份数据。

点击“试运行”会冻结完整规则快照。用户可以手动执行行动，或让所选样例策略单步运行；事件记录显示成本、产出、组合计分过程和周期结算，历史滑块恢复各步状态。修改草稿不会影响已经开始的运行。

“策略与场景”配置样例策略、种子、参与者和周期规则。“实验记录”可以运行 12 个种子的策略对照，显示实际完成、目标达成、预算截断、异常与平均步数。没有随机机制的模型不会因更换种子得到新的初始局面，样例结果不等于玩法平衡结论。

命名版本保存完整模型，可复制回草稿，原版本保留。当前模型和命名版本原子保存在项目的 `models/core.json`。项目设置支持切换模板和重置，操作前确认并在 `backups/` 保存完整副本；项目名称和历史版本保留。试运行与实验结果目前保留在当前页面会话中。

## 当前模型能力

首版支持有界整数状态、能力前置、数值效果、周期产出、顺序行动、多个阈值目标与固定的组合计分机制。组合模型具有候选集合、不同对象选择、弃置、重新洗入和补充；两类模型共用运行、校验与回放代码。

相对领先判定、复杂触发链、通用机制编程、完整集合编辑、载体原型设计及正式游戏生成尚未实现。内置样例用于验证应用结构，并非完整文明或小丑牌规则。

## 数据与接入

应用声明 `application-data`、`application-workspaces`、`workspace-files`，通过公开 SDK 选择目录、独占创建项目、登记工作区和读写 JSON。创建时若同名目录已存在，拒绝覆盖；普通编辑只改用户的项目文件。

`main/templates/*.json` 保存内置模板；`models/core.json` 保存当前模型，附带 `project` 元数据和命名版本。宿主数据库只保存 `gameplay-lab:library:v2` 项目位置索引。读取文件失败时保留原文件与索引；外部修改后拒绝旧页面覆盖，用户可从项目设置重新读取。

加载时直接清理旧版数据库项目记录，不提供旧版读取或迁移入口。当前目录项目、JSON 和备份保留。

项目文件持久化、重开、模板隔离、备份及冲突处理已用生产数据与文件服务在隔离目录中验证。`preview:packed` 提供同样的文件验收环境，选择器使用临时目录替身；真实原生目录选择交互需在 Mewvis 中使用。普通工具链开发预览不提供完整文件能力，不回退到浏览器存储。

沉浸式全屏通过宿主的 `--mewvis-safe-area-top` 预留顶部控件空间，普通布局采用宿主提供的零安全区，无须重新加载。

## 开发

```sh
pnpm --filter @mewvis/gameplay-lab dev --port 5192
pnpm --filter @mewvis/gameplay-lab check
pnpm --filter @mewvis/gameplay-lab test
pnpm --filter @mewvis/gameplay-lab test:projects
pnpm --filter @mewvis/gameplay-lab build
```
