# 角色协作插件

插件实现自定义顺序流程，自行维护角色、头像与流程，通过 SDK 使用配置和任务能力，不依赖 Pi、桌面业务模块或会话目录。

## 使用

1. 在插件管理中打开 `isle.collaboration` 的配置。外层通过“流程 / 角色”页签展示只读列表，支持搜索；流程展示步骤概览，角色展示并链接到引用它的流程。点击“添加角色”打开弹窗，填写名称、职责和头像后保存。
2. 点击“新建流程”打开流程编辑弹窗；点击已有条目可编辑。流程弹窗左侧选择步骤，右侧编辑当前步骤；添加后自动选中新步骤，可上移、下移或移除。上下文和结果判断按需展开。
3. 为每一步选择角色、填写任务说明，选择是否附加上一步或全部前序结果。
4. 保存后，在聊天输入开头输入 `/`，按流程名称选择命令（输入框和消息显示名称，后台仍使用命令 ID），再填写任务；模型也可根据流程描述调用对应工具。
5. 输入框上方依次显示流程名、执行者标签、当前步骤与进度，可以暂停、继续或取消当前流程；完成、失败或取消后状态栏自动隐藏。每一步以“步骤 · 角色”和插件自有头像独立展示实时正文、模型返回的思考与工具调用；执行期间隐藏没有内容的父助手占位，最后显示流程结果。过程消息和最终结果一起保存，重新打开会话后仍可查看。

弹窗中的保存立即写入配置并刷新列表，取消或关闭丢弃草稿。删除按钮位于外层列表，首次点击变为错误色的“确认”按钮，再次点击才删除；移开焦点取消确认；被流程引用的角色不能删除。编辑弹窗通过应用级 `plugin.dialog` 协议和宿主 `DialogSlot` 展示。

初始配置为空，不预设流程。运行使用配置和角色快照，修改配置从下一次执行生效。第一版仅支持顺序执行；原设置中的协作配置暂不迁移。

## 边界

| 层            | 职责                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------- |
| SDK           | `host.configuration`、`host.tasks`、`host.activity` 协议；设置和状态 UI 贡献；文本命令      |
| 插件          | 维护自有角色与头像、编辑流程、生成工具和命令、编排顺序、拼接输入、发布步骤状态              |
| SDK adapter   | 将 SDK 的 UI、Agent 和服务接口映射到宿主协议                                                |
| 宿主 UI       | `SettingsSlot` 展示插件编辑器；`StatusSlot` 获取活动数据并提供默认渲染，可覆盖 `render`     |
| 宿主服务      | 插件身份绑定、配置校验、当前会话活动读取、暂停、继续和取消                                  |
| Agent runtime | 运行隔离角色任务、继承当前模型和权限、处理取消和账本；通过 Pi/Mock 自己的插件适配器注册工具 |

`configuration.read` 可在设置视图和执行期间调用；`configuration.write` 只在 UI 服务实现；`tasks.run`、`activity.publish` 和 `activity.checkpoint` 只在 Agent 执行期间实现；`activity.read/pause/resume/cancel` 只面向绑定会话的 UI 视图。调用者通过 `host.supports()` 查询宿主是否支持能力。没有实现的能力会明确返回错误。

角色列表保存在插件自己的 `roles` 配置中；头像资源位于插件的 `src/roles/avatars.ts`，随插件打包，不引用宿主头像目录或 ID。删除被流程引用的角色前，需要先修改对应步骤。宿主角色的增删改不会改变协作插件配置。

执行时插件将角色名称和职责转成系统提示，通过 `tasks.run({ text, systemPrompt, title, avatar })` 提交任务及插件自有展示信息。宿主不查询角色列表，也不接收宿主角色 ID，只负责通用子任务执行。

活动协议通过可选的 `steps[].actor: { name: string }` 提供步骤执行者。协作插件从本次运行的角色快照填写名称，SDK adapter 传给宿主活动协议，状态插槽按当前步骤展示仅含角色名称的标签。步骤弹窗也显示各步执行者；未提供该字段时不显示标签。该字段只承载展示信息，不引用宿主角色资源，也不从 `detail` 文本解析角色。

每个角色步骤有独立子会话，默认不注入编排插件，避免递归启动工作流。当前实现沿用父任务选择的模型、权限和资源限制。取消会中止父任务及其当前子步骤。活动状态按插件和会话隔离，通过通用状态插槽轮询读取；步骤运行记录保留在宿主子会话中。

## 步骤之间暂停

点击“暂停”只登记暂停请求，状态显示“暂停中”，当前步骤继续执行；到达下一步前的检查点后，状态变为“已暂停”。此时已完成结果留在当前插件调用中，点击“继续”仅启动下一步，不重放前序步骤。到达检查点前可以“撤回暂停”；最后一步完成后直接结束流程，不再等待。暂停期间仍可取消。取消结束整个父任务和当前子步骤，确认退出前保持“取消中”，之后输入框才能发送下一条需求。

状态条、输入框主按钮和侧边栏共用宿主会话的 `ChatSnapshot.execution`。运行进程发布活动执行事件，宿主按版本处理暂停状态；插件完成不会被当作父任务结束。输入框在暂停时显示“继续执行”，点击只恢复当前任务，不提交草稿；侧边栏在离开聊天页后仍保留暂停状态。`PluginUIProvider` 接收原生 `UIExecutionSource` 端口，状态插槽通过它消费共享快照与取消/继续操作，不依赖桌面 Chat 实现。

检查点是通用宿主能力。插件声明 `activity.pausable`，在每个步骤启动前调用 `host.activity.checkpoint(id)`；宿主管理暂停请求和等待，插件继续负责步骤与结果。宿主未实现该可选能力时，流程仍可顺序运行，状态条不显示暂停按钮。

暂停等待不消耗插件执行预算，也不会触发 Pi 的无活动超时。当前步骤的原有执行限制仍然生效。暂停保留当前运行及会话占用，不支持暂停期间在同一会话启动另一轮，也不支持应用退出或重启后继续；关闭应用后需要重新发起流程。

## 验证

- `pnpm --filter @isle/agent-runtime test:extensions`：Mock 工具、文本命令、角色失效、子任务隔离，以及已有 Pi/Mock 插件回归。
- `pnpm --filter @isle/server test:extensions`：真实服务、SDK worker、Pi、本地模型、配置保存、命令发现、账本、暂停/继续、撤回暂停、最后一步完成、暂停中取消和会话隔离链路；不需要外部模型账号。

### 步骤结果判断

步骤可配置 `judgment: { question, output }`。执行角色完成后，协作插件将该步骤输出作为材料，通过 `host.decisions.evaluate` 获取标准判断结果。界面中的“完成后判断结果”用于配置这个入口，不选择判断插件或内部规则。

判断结果加入本步骤结果，后续步骤可通过“前序结果”引用；当前不改变步骤顺序。结果可能为 `review_required` 或 `abstained`，不能当作确定结论。没有可用提供者会在开始流程前明确报错；判断执行异常会按普通步骤失败处理。暂停仍在步骤之间生效，取消会同时终止嵌套的判断调用。
