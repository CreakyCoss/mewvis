# Mewvis 视觉系统

## 设计方向

Mewvis 是一个需要长时间停留的 AI 创作工作台。界面采用“冷白画布 + 清晰墨色 + 活力靛蓝”的现代工作台视觉语言：

- 内容优先，装饰退后；页面只保留一个明确的主操作。
- 冷白背景降低视觉噪音，纯白卡片只用于需要分组或抬升的内容。
- 主色用于主操作、选中态与焦点；状态通过 success、warning、error、info 区分，次级操作使用中性色。
- 图标统一使用 Lucide 线性图标，不使用 emoji 作为结构图标。
- 阴影只表达层级：页面卡片、浮层两级，不能在单页中随机定义多套阴影。

## 核心令牌

所有系统界面颜色以 `packages/design-system/tokens.css` 的浅色、深色语义变量为准；`theme.css` 提供 Tailwind 映射和共享样式。宿主与内置应用共同使用这套变量，组件中不新增固定色值或 `text-green-*` 等调色板类。

`theme.css` 是 `components.json` 指定的 shadcn 样式入口，也是项目维护的源码，常规构建不会重新生成它。新增语义色时在此补充 `@theme inline` 映射；日常换肤只修改 `tokens.css`。执行 shadcn 初始化、应用预设或安装带有样式的 registry 项时，需检查 CLI 对入口的改动，避免重新引入重复的颜色定义。

当前 `success` 使用低饱和、偏冷的青绿色，与靛紫主色搭配；成功状态仍通过勾选图标或文字表达。

| 角色                      | 用途                         |
| ------------------------- | ---------------------------- |
| `background`              | 页面画布                     |
| `surface`                 | 次级分区、工具栏背景         |
| `surface-raised` / `card` | 卡片、输入框、浮起内容       |
| `foreground`              | 主文字                       |
| `muted-foreground`        | 描述、辅助信息               |
| `primary`                 | 唯一主操作、选中态、焦点     |
| `success`                 | 完成、通过、正确反馈         |
| `warning`                 | 风险、等待确认、需注意       |
| `error` / `destructive`   | 错误与破坏性操作（同一色值） |
| `info`                    | 信息提示、重命名等中性变更   |
| `secondary` / `muted`     | 中性的次级操作、弱化背景     |
| `chart-1` … `chart-5`     | 图表系列、无状态含义的分类   |
| `accent`                  | 低强调选中态、图标底色       |
| `brand-pop`               | 品牌提示、微量活力强调       |
| `border` / `input`        | 分隔和输入边界               |

`primary/success/warning/error/info` 均提供 `-foreground`（实色背景上的文字）、`-subtle`（弱背景）和 `-border`（边框）。例如主要按钮用 `bg-primary text-primary-foreground`，“内置”标签用 `<Badge variant="primary">`，成功反馈用 `<Badge variant="success">`。`Badge` 和 `Alert` 均提供语义状态变体；共享 `Toaster` 也使用这些变量。

浅色与暗色必须同时使用语义变量，不在内容组件里写 `bg-white`、`bg-black/*` 或页面私有灰色；浮层遮罩使用 `bg-overlay/45`。分类颜色不借用成功或警告语义，改用 `chart-*`。

应用 iframe 由宿主注入 `tokens.css` 作为默认值，并在 `host:init`、`host:theme` 中传递宿主已解析的 `themeTokens`，自动应用到 iframe 根节点。宿主根节点的 `class`、`style`、`data-theme` 变化都会同步，因此仅修改主色也能更新已打开的应用，无需应用各自维护深浅两套颜色。原有 `isle:theme` 事件仍以浅色/深色字符串为 detail。普通 CSS 应用直接使用 `var(--primary)` 等变量；应用内不要覆盖共享语义变量为固定颜色。

本轮统一范围包括应用管理/市场、聊天任务与文件状态、共享浮层与提示、故事通用场景、文档中心、RSS、学习工作台和聊天调试台。森林、赛博、武侠等明确的场景主题，以及办公室和学习首页插画保留独立艺术配色。

## 排版

- 应用基础字号：15px，行高 1.5。
- 页面标题：20–24px，600 字重。
- 区块标题：16–18px，600 字重。
- 正文与交互标签：14–15px，400/500 字重。
- 辅助信息：12px；只用于状态、时间、计数，不承载关键操作说明。
- 中文使用系统无衬线回退；沉浸式故事正文可使用 `font-serif`。

## 间距、圆角和层级

- 间距遵循 4px/8px 节奏，页面常用 16/24/32px。
- 输入、按钮最小高度 36px；独立图标按钮的可点击区域不小于 36px，关键触摸操作不小于 44px。
- 控件圆角 8–10px；卡片 12–14px；胶囊只用于标签、筛选和状态。
- 页面抬升卡片使用 `.app-panel`，可点击卡片使用 `.app-interactive-card`。
- 空状态使用 `.app-empty-state`，必须包含标题、解释和可执行的下一步。

## 页面结构

页面优先采用以下层级：

1. 统一页面头部：图标、页面标题、单行说明、主要操作。
2. 可选的筛选/标签栏。
3. 限宽主内容区；长文保持可读行长。
4. 空状态或内容网格。

侧栏负责全局导航和最近内容，不应与页面主标题争夺视觉权重。

## 弹窗与反馈状态

- 表单弹窗使用“抬升头部 + 画布内容 + 固定操作栏”三段结构；内容过高时只滚动中段，头部和主操作保持可见。
- 弹窗标题区可使用 40px 的强调图标底座，说明保持一到两行；关闭按钮位于右上角，异步提交期间可禁用关闭。
- 模态遮罩统一使用约 45% 的深色 scrim，并只用轻微背景模糊隔离层级；确认框、表单弹窗和侧滑面板不得各自定义不同强度。
- 下拉菜单、选择器和悬浮信息卡统一使用 12–14px 圆角、浮层阴影和语义边框；菜单项与选择项高度不小于 36px。
- 表单字段必须有持续可见且与控件关联的标签；可选字段在标签旁标注，不依赖 placeholder 充当标签。
- 异步提交按钮同时禁用并展示加载图标，避免重复提交；长任务使用 `role="status"` 和 `aria-live="polite"`。
- 错误使用语义化 `Alert` 或 `role="alert"`，不能只依赖红色；提示应说明发生了什么，并在可行时给出恢复路径。
- 破坏性操作必须二次确认，并使用 `destructive` 语义样式；取消操作始终保持次要层级。
- 列表空状态必须说明为什么为空，并提供最直接的下一步；加载状态需要与空状态在文案和图标上明确区分。
- 页面内切换一级视图时重置内容滚动位置，避免新页面从旧页面的中段开始显示。
- 动态对象与数组表单必须形成清晰的分组表面，新增、删除和空状态都要有明确文字；标签与控件通过 `htmlFor`、`aria-label` 或 `aria-labelledby` 关联。
- 自定义页签遵循标准 tab 语义，支持左右方向键以及 Home/End 导航，当前页签之外的项不进入普通 Tab 顺序。

## 交互与无障碍

- 所有交互有 hover、pressed、focus-visible、disabled 状态。
- 焦点使用 2–3px 的 `ring` 语义色，不移除键盘焦点。
- 动效保持 150–250ms，并遵循 `prefers-reduced-motion`。
- 图标按钮必须提供 `aria-label`。
- 普通正文对比度至少 4.5:1；状态不能只通过颜色表达。

## 对话与执行过程

- 助手消息使用 `.app-message-surface` 形成完整但克制的阅读纸面；用户消息保持紧凑的 `primary` 气泡，两者不能混用同一背景层级。
- 思考与工具调用统一使用 `.app-process-block`、`.app-process-trigger`、`.app-process-content`；运行、完成、异常必须同时呈现图标或文字，不只依赖颜色。
- 已完成的长过程可以自动收起，但必须保留用户手动展开后的选择；折叠按钮提供 `aria-expanded` 和明确的状态说明。
- Markdown 正文保持 14px / 24px 的阅读节奏，超长链接和文本允许换行，代码与表格只在自身容器内横向滚动。
- 加载状态使用 `role="status"`，错误使用 `role="alert"` 并给出恢复方向；提问卡片的输入必须有持续可见标签。

## 沉浸式故事场景

- 酒馆可按题材保留独立背景、气氛色和消息材质，但按钮高度、焦点环、错误反馈、加载状态和键盘语义仍遵循全局设计系统。
- 角色、用户、旁白三类消息必须有稳定的布局方向和可访问名称；角色头像、消息正文与时间信息形成一个阅读单元。
- 流式生成仅在用户停留于末尾时自动跟随；用户向上阅读后不得强制回底，并提供明确的“回到最新”操作。
- 角色设定不能只依赖悬停查看，触发卡片必须可聚焦并支持点击或触控。
- 故事输入区明确提示发送、换行和文件引用方式；文件建议项拥有至少 40px 高度、hover 与 focus-visible 状态。
