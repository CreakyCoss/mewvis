# 棋盘经济：环形经济棋盘

创建项目时选择“棋盘经济 → 环形经济棋盘”，从空白配置自己的双人棋盘。棋盘、位置、资金和地产归属使用独立规则模型；资源发展、卡牌和叙事项目继续使用各自的模型。

## 从空白开始

1. 在“棋盘与规则”添加起点和其他地块。至少 4 格，最多 20 格，首格须为唯一的起点，至少一格为地产。
2. 给地块命名，选择起点、地产或休息地。地产设置购买价格与落地租金；起点和休息地不收费。
3. 配置两位玩家的不同名称、初始资金、经过起点收入、骰子面数和回合上限。
4. 在就绪检查通过后“开始试玩”。草稿可在地块数量、名称或价格尚未完成时保存；未就绪的规则不能开始对局。

上移、下移和复制会改变棋盘草稿的顺序，末格始终连接首格。复制后标识独立；如果复制了起点，需要把多余起点改成其他类型。规则修改只影响新开局，不移动历史棋盘上的地产或棋子。

| 配置           | 支持范围                                  |
| -------------- | ----------------------------------------- |
| 地块           | 4–20 格，按编号顺时针组成环形             |
| 玩家           | 固定 2 位，名称 1–40 字                   |
| 地产价格与租金 | 每项 1–1,000,000                          |
| 初始资金       | 每位玩家 1–1,000,000                      |
| 起点收入       | 每次经过 0–1,000,000                      |
| 骰子           | 2–6 面，每次前进 1 至面数的格数           |
| 回合上限       | 1–200，每位玩家掷骰并完成落点结算算一回合 |
| 随机种子       | 0–4,294,967,295，开局冻结                 |

## 掷骰、购买与收租

轮到自己时“掷骰前进”。棋子从起点出发，沿编号前进并在末格后回到起点。经过或落在起点都会领取收入；一次跨过多圈则按次数领取，先领收入再结算落点。

- 空置地产：现金足够时选择购买或跳过。购买扣除价格并登记归属，再轮到对手；买不起时自动跳过。
- 对手地产：自动支付租金，金额转入对手现金。落到自己的地产不再付款。
- 休息地和起点：完成收入及落点结算后轮到对手。

现金不足支付租金时，支付全部余额、把自己的地产移交债权人，并判对手获胜。刚好付清租金而现金为 0，不立即破产；之后若有无法支付的租金才破产。首版使用现金支付，不包含抵押、建房或拍卖。

达到回合上限时结束并记录“未判胜负”，不按现金或地产数量推断赢家。最后一回合若停在购买选择，先完成购买或跳过再检查上限。

## 自动玩家与查看棋盘

“自动玩家走一步”执行当前玩家的一次合法操作。基础策略会购买现金足够且购买后仍保留起点收入等额现金的地产，否则跳过。也可勾选“自动控制”接管第二位玩家，自己操作第一位玩家；控制项显示对应玩家的自定义名称。

自动对手在关闭试玩、打开检查面板、查看历史步骤、保存忙碌或操作出错时暂停。返回当前对局后可继续。双方的资金、位置和地产归属都是公开信息。

点击地块可查看价格、租金和归属。窄屏下大棋盘在自己的区域内滚动；编号明确行动顺序，空白连线区不算地块。

试玩采用随宿主明暗主题切换的桌游界面：双方资产位于棋盘上方，地块通过颜色和玩家名称标明归属；掷骰后默认查看落点。右侧集中展示所选地块、当前行动、购买后余额和最近三条真实事件，查看其他地块不会改变待购目标。窄屏将当前行动移到棋盘下方，仍可查看地块详情。回放进度在“检查与回放”中操作；历史棋盘与实验样本的操作按钮均保持只读。

每次操作保存成功后，试玩依次展示骰子结果、棋子按编号逐格前进及资金结算。经过起点时显示对应收入，购买与付租分别标明支出，收租方同步显示收入；破产支付显示实际余额，不把应付租金当成已支付金额。收入和支出分项保留，即使净变化为零也能看清原因。移动期间突出当前经过的地块，最后标注落点；窄屏大棋盘会在自身区域水平跟随棋子。

“跳过动画”立即显示本次已保存的结果，自动对手会等待本次展示结束后再行动。关闭试玩、进入检查或历史回放、切到后台时会结束当前展示；重新打开或刷新直接恢复已保存状态。系统开启减少动态效果时不播放逐格动画，仍保留收支说明。历史棋盘与实验样本始终直接显示对应状态，不重新播放实时移动或执行命令。

## 保存、版本与回放

每次操作先在副本上执行并保存，写入成功后更新棋盘。写入失败不发布新的骰子、现金或归属；重试仍按同一冻结种子和上次已保存状态计算。对局关闭或刷新后，在“试玩记录”继续未结束的对局。

“版本”保存当前棋盘与规则，最多 10 份；复制回草稿不改写已有对局。每局冻结地块顺序、价格、租金、起点收入、玩家名称和种子，即使草稿改动，也按开局时的规则继续。

拖动“棋盘回放步骤”或在“检查与回放”选择事件，即可查看当时的资金、位置和归属。回放不能掷骰或购买，点击“回到当前对局”才恢复操作。读取记录时重放全部命令并核对最终状态，损坏或不兼容的文件保留并单独提示。

## 一份从空白配置的验收棋盘

“港湾棋局”按顺序配置港口（起点）、码头（价格 5、租金 30）、市场（价格 5、租金 30）、广场（休息地）；每位玩家初始现金 20、起点收入 0、2 面骰子、20 回合上限、种子 42。

玩家 1 先掷出 1，停在码头。此时关闭并刷新，再从记录继续购买，现金变为 15。玩家 2 下一次也掷出 1，落到码头，应付租金 30、实际支付余额 20，玩家 1 以现金 35 获胜。回放到购买前，归属恢复为空；回到购买后，归属为玩家 1、现金为 15。

验收使用隔离临时项目与生产文件服务，不写入真实用户项目。截图位于本地 `output/gameplay-lab/board-economy-qa/`。

## 多种子实验与版本对照

在“自动实验”选择单版验证，或选择两个不同的规则来源做版本对照。来源可以是当前草稿或命名版本；两份规则的地块或规则内容须不同。开始时冻结规则、来源名称、模拟器与基础自动策略 v1，之后修改草稿或版本不影响续跑。

种子从起始值连续递增，不回绕；单版最多 240 个种子，两版对照最多 120 个种子、共 240 局。双方都使用与试玩相同的基础自动策略，第一位玩家固定先手。对照按同一种子交替运行基准、候选，再进入下一种子。

实验先保存计划，再逐局保存结果。取消会等待正在写入的完整样本保存，之后可“继续实验”；刷新或重新打开时，遗留的运行中实验显示为已中断。续跑只处理缺少的版本与种子，已保存的执行错误也保留，不自动重跑。写入失败不发布未保存的进度，重新加载后可继续。返回项目库会先取消并等待保存。

结果按规则分别显示先手胜率、后手胜率、平均回合、破产率、上限率和错误数。胜率、破产率与上限率均以成功执行到终局的样本为分母，达到上限也计入分母但不计为任何一方胜利；执行错误排除。平均回合是每位玩家完成一次掷骰与结算的回合数。配对差异只使用两版都成功执行的同种子样本，显示候选减基准的平均局长和先手胜率百分点差。

高上限率会降低双方胜率，不能单凭先手胜率下降判断先手优势减小。上述港湾棋局用种子 42–141 对照租金 30 与租金 1：原规则平均约 3.7 回合、先手胜率 61%；低租金平均 20 回合、全部达到上限、双方胜率均为 0。它说明这组配置和种子下低租金使局长增加，尚不能判断低租金下的先手优势。

可按规则、破产/上限/错误结果和完整种子筛选样本，每页 10 局。“回放样本”使用该实验冻结的规则，逐步查看资金和归属；“查看样本末步”仍只读，不创建或修改试玩记录。实验验收截图位于 `output/gameplay-lab/board-experiments-qa/`。

## 开发边界

`gameplay-board-economy-v1` 与 `board-economy@1` 实现独立的 `GameRuntime`，不套用数值计分模型。通过统一框架登记进入创建页和自己的工作区；没有内置示例或额外预填地产。

共享 `shared/random.ts` 的整数随机序列、项目目录服务、原子文件写入、命名版本、试玩窗口和记录仓库。卡牌随机 API 保留原顺序。棋盘对局使用 `gameplay-board-economy-run-v1`，保存冻结模型、命令、手动或基础自动来源及最终状态。项目模型仍在 `models/core.json`，记录仍在 `runs/`。

棋盘实验使用 `gameplay-board-economy-experiment-v1`，文件保存在独立 `experiments/` 目录，单文件上限 16 MiB；普通试玩记录仍在 `runs/`，上限 4 MiB。每个版本只存一份规则，各样本保存命令与最终状态；读取时检查唯一种子单元、策略命令、版本和重算结果。仓库复用已验证样本的内容指纹，规则或样本变化时重新验证。

外部修改继续受文件时间和内容检查保护。若外部把同一项目改成另一类型，旧工作区重新读取会拒绝继续覆盖，需要从项目库重新打开。当前未提供抵押、拍卖、建房和多人地产规则。
