# 卡牌组合计分

“卡牌 → 组合计分”使用独立的 `gameplay-card-v1` 模型和 `card-combination@2` 模拟器。卡牌定义、牌库构成与运行中的实体牌分别保存；通用数值状态、行动、成本、目标和周期效果继续复用数值规则基础。

## 从零开始

1. 新建卡牌项目，选择“组合计分”，创建方式保持“从零开始”。
2. 在“卡牌与回合”添加卡牌定义，填写名称、说明、分组和基础值。添加牌库，将卡牌加入其中并填写数量。
3. 设置手牌容量、开局抽牌数、最少/最多出牌数、补牌时机与弃牌回收方式。
4. 在“规则定义”添加得分状态、计分行动及目标。行动添加“组合计分”效果，选择牌库、得分状态、倍率与同类配对奖励。
5. 就绪检查通过后开始试玩。每张副本可单独选中；选牌不足或超量时，行动显示原因并禁用。一个行动只使用其引用牌库中的选牌。

例如，定义“晨光”基础值 2 和“月色”基础值 4，每种各 2 张；手牌、开局抽牌和出牌数量均设为 2，出牌后补牌，弃牌不回收，固定倍率 1、配对奖励 0、目标 12。两次提交用完四张牌即可完成目标。

## 抽牌与牌区

- 每位参与者按牌库构成生成自己的实体牌，使用固定种子洗牌。实例保存卡牌定义引用与独立标识，不会将牌库数量展开写回项目规则。
- 开局只抽“开局抽牌数”，不立即补满容量。开局抽牌数不能超过手牌容量；牌库必须足够完成开局抽牌及最少出牌。
- 组合计分依次执行行动效果，所选实体牌从手牌进入弃牌区。“出牌后补满”在这一步补牌；“自己的行动阶段开始时补满”在该玩家下一次开始行动时补牌；“不自动补牌”保留剩余手牌。
- 抽牌区耗尽时，可选择将弃牌洗回后继续抽取，或停止抽牌。停止时不凭空生成牌，手牌可能少于容量；不足最少出牌数的行动不可执行，仍可执行其他合法行动或结束阶段。
- 轮换时先执行已有周期结算及结束判断，未结束才为下一位玩家补牌。已达成目标或达到轮数上限后不额外抽牌。
- 目标仍在每次行动及周期结算后检查。自动策略同样遵守最少出牌数和有限牌库约束，不将无法出牌误记为结算异常。

每种卡牌在一个牌库中只出现一行，数量为 1–100；最多 100 种卡牌、20 个牌库，每个牌库最多 500 张。手牌容量和出牌数量为 1–10，开局抽牌数为 0–10。未完成的草稿可以保存，引用和数量关系在试玩前完整检查；不支持的规则字段会被拒绝。

## 记录与实验

试玩界面提供各玩家抽牌区、手牌区和弃牌区的快照检查，事件显示牌名和副本编号。逐步回放恢复当时的牌区与得分；历史游标只读。

命名版本冻结卡牌定义、牌库数量、抽补牌方式及其他规则。数值对局使用 `gameplay-run-v3`，实验使用 `gameplay-experiment-v4`，共同冻结模拟器 v2。修改草稿不会改变旧运行，读入时根据冻结内容重算并核对。

版本对照要求模拟器标识、版本及模型格式一致。单参数扫描除现有数值规则外，支持卡牌基础值、牌库内某种牌的数量、手牌容量、开局抽牌数及出牌上下限；每个扫描点必须满足完整规则校验。扫描不修改当前草稿。

## 当前格式与不兼容数据处理

内置卡牌示例 JSON 直接使用当前模型。应用不再读取或执行旧集合卡牌模型与 `card-combination@1`，也不提供升级或迁移入口。

加载遇到不兼容项目或命名版本时停止打开并提示，原项目文件、版本与备份保持不变。不兼容记录单独提示，当前记录仍能读取。用户可查看路径、原因及删除范围；只有再次确认后才删除选中的项目或记录，取消保留数据。删除期间发生外部修改会拒绝执行，需重新加载并再次确认。

当前不包含卡牌战斗、任意触发链、奖励、商店或跨关卡构筑。这些机制需要分别补齐对应的编辑与执行语义。
