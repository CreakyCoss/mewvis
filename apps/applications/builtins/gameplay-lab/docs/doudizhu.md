# 斗地主框架

本框架提供完整的基础三人叫分玩法。用户编辑自己的出牌与结算参数，系统提供固定结构、专属执行器和牌桌。它与组合计分是同属卡牌类型的两个独立框架。

## 创建与配置

手动新建项目，类型选择卡牌，玩法框架选择斗地主，选择经典斗地主或英雄斗地主作为起点预设，填写项目名称与父目录。框架自带固定 54 张扑克牌和必要流程。经典预设与用户自定义方案共用[玩法组合与模块装配](composition.md)。

在“牌型与结算”可以开关对子、三张、三带一、三带二、顺子、连对、飞机、飞机带单/对、四带两张/两对、炸弹、王炸；单张不可关闭。可以调整顺子的最少张数、连对的最少对数、飞机的最少组数、带单是否要求不同点数、炸弹倍率及基础分。当前通过受控参数配置规则，不支持任意编写新牌型脚本。

不同规则模型的框架不能通过设置直接互相解释，需分别创建项目；其他框架的示例不能覆盖斗地主项目。

## 执行约定

- 54 张实体牌按种子洗牌，每人 17 张，保留 3 张底牌。
- 三人依次叫 0–3 分，非零叫分必须超过当前最高分；叫到 3 分立即结束，三人均不叫则重新发牌。最高叫分者成为地主并获得底牌，地主先出。
- 普通牌型按同类型、同张数、同连续长度比较主体点数。2 与大小王不能进入连续主体；三带、飞机和四带的附带牌不参与大小比较。
- 飞机附带牌不能来自主体点数；带单可允许对子拆作两张，但最多每个点数两张。带对要求不同点数的对子。四带两张使用同样的带单开关，四带两对要求不同对子。带牌不能同时包含大小王。这些是本框架明确选择的规则变体。
- 炸弹可压普通牌型，高点数炸弹压低点数炸弹，王炸最大。四带牌属于普通牌型，不是炸弹。
- 跟牌可以过牌；连续两人过牌后，由最后出牌者重新领出。领出时不能过牌。
- 任一玩家出完手牌后立即结束。地主或两位农民共同胜负，单个农民分值为基础分 × 叫分 × 累积倍率，地主承担两倍；不计算春天。

## 游玩和记录

玩家控制座位 1，另外两人由基础自动玩家操作。牌桌只接收自己的手牌、对手张数和公开出牌，底牌在叫分结束后公开。自动玩家只接收自己座位的玩家视图，并按固定规则选择合法操作；它不是高水平斗地主 AI。

手牌支持鼠标和键盘选择，可查看提示后出牌或过牌。对手自动响应；关闭窗口、进入检查面板、历史回放或操作失败时暂停。保存成功后才显示新的对局状态，失败可重试，原状态仍保留。

规则保存在 `models/core.json`，规则版本冻结在该文件中；对局保存在 `runs/`。每局冻结规则、执行版本、种子和全部命令。重开项目后可以继续，回放按原规则重算并校验最终状态。修改草稿只影响新开的对局。

检查面板可以主动展开全部手牌，属于策划检查工具；正常牌桌和自动玩家不会因此获得额外信息。回放阶段不执行操作。

## 模块边界

`model.ts` 定义可编辑结构，`rules/` 负责牌型识别和比较，`runtime/` 负责流程与玩家视图，`bots/` 提供自动决策，`editor/` 和 `play/` 提供具体界面。`records.ts` 负责冻结和重算，`repository.ts` 将记录接入公共文件仓库。

当前提供一个可开关的英雄洞察模块。抢地主、春天、跨局成长和专属批量实验尚未提供。未知模块和不支持的版本会提示并保留数据，只有用户明确确认后才能删除。

### 英雄洞察模块 v1

在“玩法组合”启用英雄模块，侧栏会出现“英雄与技能”编辑页，可为三位座位分别配置英雄名、技能名、每局使用次数（1–3）和每次查看张数（1–3）。系统提供的技能效果是洞察：出牌阶段轮到自己时，选择另一名有手牌的玩家，随机查看其手牌。使用技能不消耗出牌机会，也不改变牌区、跟牌关系或倍率；叫分与结束阶段不能使用。连续使用按命令顺序结算。

牌桌显示自己的技能、目标选择与剩余次数，并显示其他玩家的英雄名和公开使用次数。被查看的牌只进入使用者的玩家视图，公共消息不含牌面。结果标记为当时的快照，后续可能被打出。检查工具仍可主动查看完整状态；正常牌桌与自动对手各自读取玩家视图。

基础自动对手会在自己的出牌回合使用可用技能，农民选择地主，地主选择剩余手牌较少的农民，然后继续正常出牌。这只是基础决策，不代表洞察策略经过优化。

模型通过 `composition.modules` 引用模块版本，并通过 `extensions.heroes` 冻结模块版本（`version: 1`）、开关及三席配置；技能明确记录 `timing: "before-play"` 与 `effect: "peek"`。未知时机或效果被校验拒绝，暂不提供任意技能脚本。模块目录 `extensions/heroes/` 同时包含结构校验、确定性运行、编辑器、牌桌组件和样式，通过运行与界面注册表接入骨架。

每次技能是独立的 `skill` 命令，记录技能标识与目标。随机查看由冻结种子、发牌轮次和命令位置决定，保存、续玩和逐步回放可重现相同结果。关闭模块保留编辑配置，新开局不创建英雄状态和交互；修改草稿不会改变已有记录。未配置模块的原有 v1 对局继续按基础规则重算，无需迁移。
