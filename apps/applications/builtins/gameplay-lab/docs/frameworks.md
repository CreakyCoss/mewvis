# 玩法框架与游戏试玩

日期：2026-10-29。产品主流程为选择框架、创建方案、编辑内容与参数、在独立游戏窗口试玩、根据记录与实验调整。

## 框架提供什么

类型用于分类，框架定义可执行的内容结构、流程、结算、专属编辑器和游玩界面。用户设计自己的内容与可配置规则，自动玩家的决策逻辑另称“策略”。

组合计分和斗地主目前提供专属配置和独立牌桌。斗地主使用自己的规则模型，经典斗地主、英雄斗地主及用户自定义方案共用[玩法组合与模块装配](composition.md)，详见[斗地主说明](doudizhu.md)。回合资源发展、条件分支叙事保留现有编辑与验证能力；棋盘与塔防仍未提供，不能通过切换类型名称获得对应玩法。

## 从零创建组合计分方案

1. 手动新建项目，类型选卡牌、框架选组合计分，保持从零开始，填写名称与父目录。
2. 框架准备累计得分、提交组合、得分目标及空牌库。不插入示例卡牌，也不自动创建项目。
3. 在“卡牌”设计名称、分组、基础分和说明，在“牌库”设置卡牌数量及抽补牌规则。
4. 在“计分与回合”调整配对奖励、倍率、目标和轮数。额外的资源、行动与效果可以在高级规则中编辑。
5. 概览检查通过后点击“开始试玩”，进入独立牌桌。

例如，晨光基础分2、月色基础分4，各2张；手牌及开局抽牌均为2，最少/最多出牌均为2，配对奖励0、固定倍率1，弃牌不回收，目标12。两次提交用完四张牌即可结束本局，全程无需手动搭建得分状态与计分行动。

## 牌桌体验

- 点击实体手牌选择组合，显示基础分、配对奖励、倍率及预估得分；达到选择上限后仍可取消已选卡牌。
- 提交组合由正式执行器结算，抽牌与弃牌计数、目标进度及回合状态随保存成功更新。
- 已有当前格式方案中的额外行动仍可使用；成本不足、手牌不足或本局结束时禁止相应操作。
- 可以结束行动或让本局冻结的自动玩家走一步。界面不会替玩家预选手牌。
- 达标或达到轮数限制后显示结束状态，可新开一局；新局使用当前方案，旧局保留自己的规则。
- 窗口可展开、缩小或关闭，关闭不删除对局。再次打开本局可以继续，实验样本和历史游标只读。

“检查与回放”面板展示原有状态、牌区和事件，可逐步回放。切回牌桌时保留游标，回放期间不能执行操作，返回当前对局后恢复游玩。

牌桌是规则的可玩界面，不定义另一套结算逻辑。预估只代表组合计分部分，最终结果还包括行动成本、其他效果与周期结算；失败不提交部分状态。

## 后续扩展

新的玩法框架需要一起交付结构、编辑、校验、执行、游玩与记录语义。卡牌战斗、闯关构筑等不作为当前组合计分的隐式承诺；先验证当前完整流程，再分别规划。斗地主提供可开关的英雄洞察模块，包括配置、目标选择、执行、私有视图、自动对手及回放；春天、抢地主和任意脚本规则尚未提供，未知扩展会明确阻止加载。
