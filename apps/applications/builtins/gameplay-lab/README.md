# 游戏沙盘

首版实现可编辑的关系工作台，以及“创建项目 → 定义模型 → 试运行 → 回放 → 策略对照 → 命名版本”的闭环。作为 Mewvis 独立内置应用，复用应用数据 SDK 和宿主主题。

应用图标使用沙盘意象探索中用户选定的最后一版“关卡搭建”，由内置 ImageGen 参考现有应用图标生成，采用圆角底板和柔和哑光质感。`assets/icon-sandbox.png` 为保留圆角外透明通道的 256px 正方形版本（约 98 KiB），同时用于宿主应用列表与页面顶栏。原图和生成提示词保存在本地 `output/gameplay-lab/icons/sandbox-options/`。

```sh
pnpm --filter @mewvis/gameplay-lab dev --port 5192
pnpm --filter @mewvis/gameplay-lab check
pnpm --filter @mewvis/gameplay-lab test
pnpm --filter @mewvis/gameplay-lab test:projects
pnpm --filter @mewvis/gameplay-lab build
pnpm --filter @mewvis/gameplay-lab preview:packed
```

开发预览：`http://127.0.0.1:5192/`。工具链预览使用隔离内存，不提供完整的真实文件服务；项目目录流程使用 Mewvis 宿主或 `preview:packed` 验证，不回退到浏览器存储。

应用每次打开先进入项目库。没有用户项目时显示空态，内置模板不自动变成项目。创建时填写名称、选择策略模板和父目录，按项目名新建独立文件夹；目录已存在则拒绝覆盖。创建成功后进入工作台，项目库显示各自的文件路径；“打开项目”可以重新加入已有的项目目录。

`preview:packed` 使用生产沙盒桥接、数据服务、工作区登记、SQLite 和文件 SDK，在系统临时目录中验证；“选择”使用验收父目录，“打开项目”选择临时目录内的首个项目，目录选择器为验收替身。界面刷新会重新读取临时文件和索引；退出验收服务会清理临时目录。该服务与真实应用数据隔离；`?theme=dark` 检查深色主题。生产宿主使用真实目录选择器。

## 模板与项目文件

内置模板分别位于 `main/templates/development.json` 和 `main/templates/combination.json`，只在用户创建、切换或重置模板时复制内容。模板不会随项目编辑而变化，应用升级也不会自动覆盖项目规则。

```text
用户选择的父目录/
  项目名/
    models/
      core.json                  # 当前规则及项目元数据、命名版本
    runs/
      run-标识.json               # 规则快照、种子、逐步决策、事件及最终状态
    experiments/
      experiment-标识.json        # 实验计划、规则快照与逐局样本
    backups/
      时间-规则标识.json           # 切换、重置之前保存的完整副本，按需创建
    .mewvis/workspace.json        # 宿主维护的目录登记
    workspace.db                 # 宿主维护的工作区数据库
```

`models/core.json` 的顶层字段是 `gameplay-model-v1` 模型，`project` 字段保存 `gameplay-project-v2` 元数据（项目 ID、模板 ID、创建时间、命名版本）。解析时分离元数据，运行器仍只接收模型。规则与元数据在同一个文件中原子保存，模型可由外部编辑器修改。

宿主的 `application-data` 只保存 `gameplay-lab:library:v2` 项目索引（ID、登记工作区、名称和路径），不保存当前规则和命名版本。打开项目会重新读取 JSON；自动保存携带文件修改时间，外部变更后拒绝覆盖，可在项目设置确认后重新读取。

项目设置支持修改名称、查看目录与模型文件、切换模板、重置当前模板。切换与重置需要确认，先备份当前 JSON 到 `backups/`，再替换规则；项目身份、名称和命名版本保留，已经开始的运行继续使用原快照。

应用加载时直接删除旧版 `gameplay-lab:workspace:v1` 数据，不提供旧版读取、恢复或迁移入口。新建的目录项目及其 JSON、命名版本和备份不受影响。

对局写入 `runs/*.json`，对照实验写入 `experiments/*.json`，不再按页面会话截断保留数量。对局每次决策、实验每局样本完成后原子保存，保存失败不会把未写入的结果显示为已完成。重新打开项目后可继续未结束的对局，查看事件并逐步回放；取消或中断实验可继续剩余样本，已完成的策略/种子单元不会重复运行。

记录带有引擎版本、完整规则快照、种子、参与者数、决策及事件，并保存最终状态。对局还记录每步由手动还是哪个内置策略驱动。实验只保存一份共享规则，各样本分别保留决策、事件、结果和异常。读取时用固定规则重算并核对事件与最终状态，不依赖当前草稿。损坏或不兼容的记录会被单独提示并保留原文件；外部改动需点击“重新加载记录”后再继续，旧页面不能覆盖。单个记录上限 16 MiB。

## 可操作内容

- 项目库首页采用紧凑列表，集中展示项目名、说明与行动和目标数量。页标题、项目名、说明与统计分别为 18px、14px、13px 和 12px，桌面列表行最小 80px；窄屏将统计移到说明下方，项目内导航在进入项目后出现。
- 新项目明确选择“多路径发展”或“组合计分”策略模板，并创建自己的项目文件。
- 关系图和定义列表共用模型；右侧修改成本、效果、前置能力、初始状态和目标。高级规则支持增加或移除成本、数值/能力/组合效果，配置数值来源、集合、倍率与每对同类奖励。定义可复制、删除；删除前列出成本、目标、前置、效果及周期结算中的引用，存在引用时先解除。
- “规则与集合”编辑每阶段行动数、轮数、周期固定收入/按状态产出/授予能力，以及集合容量、选择上限和对象名称、分组、基础值；集合支持新增、复制和删除。未完成的集合可保存草稿，运行前必须通过完整校验。
- 图中的连接由消耗、效果、前置与目标引用生成，不能随意画出没有执行语义的连接。
- 试运行冻结完整模型；可手动决策、样例策略单步、结束行动、查看事件和历史状态。所有规则检查与结算共用纯 TypeScript 引擎。
- 两种样例共用运行器。资源发展使用库存、周期产出与前置能力；组合计分使用有序集合、选择约束、同类奖励、倍率、弃置与补充。
- 支持 1–2 位参与者、轮流行动、每阶段 1–10 次行动、最多 100 轮；200 步作为运行预算。目标在每次行动及周期结算后检查，同一检查点同时达成时保留共同结果。
- 对照实验用连续的 12 个种子比较当前策略和简单基线，报告完成、目标达成、截断、异常及平均步数。缺少随机机制时会重复相同局面，不据此宣称平衡或有趣。
- 草稿自动保存，未完成的草稿可保留；试运行和命名版本需要通过完整校验。版本最多 10 个，复制回草稿不会覆盖原版本。

## 字体与布局密度

参考影视工坊、设计工坊和调试台的工作区密度，应用使用系统无衬线字体，保留宿主明暗主题。`main/styles.css` 的 `--lab-*` 变量统一控制标题、正文、控件和面板留白，适用于项目库、模型、策略、试运行、实验、版本及弹窗。

| 用途                  | 桌面规格              |
| --------------------- | --------------------- |
| 页面和编辑器标题      | 18px / 26px，字重 600 |
| 分区标题              | 16px / 24px，字重 600 |
| 项目名                | 14px / 20px，字重 600 |
| 正文与表单            | 13px，行高 1.5        |
| 说明与统计            | 12px，行高 16–20px    |
| 按钮与输入框          | 最小高 32px，圆角 6px |
| 页面 / 面板内边距     | 24px / 16px           |
| 顶栏 / 导航行高度     | 48px / 36px           |
| 侧栏 / 定义编辑器宽度 | 176px / 288px         |

关系图最小尺寸为 640 × 440px，节点宽 136px、最小高 56px，随工作区剩余空间扩展。宽度不足时保留图内滚动；定义列表独立滚动，避免较长列表覆盖下方编辑器。窄屏保留主要按钮的 44px 点击高度及输入框的 16px 字号。

## 执行与数据边界

`main/model.ts` 定义实际支持的 `gameplay-model-v1` 子集与校验；`main/engine.ts` 执行纯状态转移，先复制再整体提交，非法选择、资源不足或数值越界不会留下部分支付。回放依据固定模型、种子与动作，测试覆盖补充集合时的确定性和对象守恒。

首版状态使用有界非负整数，效果支持数值增加、授予能力与已登记的组合计分。目标为阈值条件，可配置多个目标；尚未实现相对领先、持续倒计时、任意表达式、通用实体组件编辑、自由机制模块加载或同时行动。集合内容和配对奖励可编辑；计分仍限于基础值、同组配对奖励与状态倍率这一机制，未提供任意公式或新的计分机制编程。

策略目前为内置的目标优先、先发展和随机合法样例，没有外部脚本、LLM 调用或通用策略编程界面。AI 按钮替换为实际可用的使用指南。载体设计、正式游戏生成与完整文明策略规则属于后续迭代。

首版面向单页面编辑，尚未实现多窗口变更合并。真实宿主的持久化行为需在 Mewvis 中启用应用后验证；独立预览只验证 SDK 适配下的工作流程。

本地设计证据与验收记录见 `design-qa.md` 和 `qa/`；目录流程验收位于 `output/gameplay-lab/project-flow-qa/`，规则编辑与记录持久化验收位于 `output/gameplay-lab/rules-history-qa/`。这些探索与验收产物独立保留。
