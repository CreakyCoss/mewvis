# 游戏沙盘

按玩法框架组织策划，提供“选择框架 → 手动建项 → 编辑自己的内容与规则 → 独立窗口游玩 → 记录与实验验证”的闭环。组合计分框架提供专属配置与可玩的牌桌。作为 Mewvis 独立内置应用，复用应用数据 SDK 和宿主主题。

开发时先看[代码结构与依赖约定](docs/architecture.md)。入口只负责项目库与工作区切换，项目管理、数值玩法、文字冒险、公共组件和样式分别维护。

应用图标使用沙盘意象探索中用户选定的最后一版“关卡搭建”，由内置 ImageGen 参考现有应用图标生成，采用圆角底板和柔和哑光质感。`assets/icon-sandbox.png` 为保留圆角外透明通道的 256px 正方形版本（约 98 KiB），同时用于宿主应用列表与页面顶栏。原图和生成提示词保存在本地 `output/gameplay-lab/icons/sandbox-options/`。

```sh
pnpm --filter @mewvis/gameplay-lab dev --port 5192
pnpm --filter @mewvis/gameplay-lab check
pnpm --filter @mewvis/gameplay-lab test
pnpm --filter @mewvis/gameplay-lab test:projects
pnpm --filter @mewvis/gameplay-lab build
pnpm --filter @mewvis/gameplay-lab preview:packed
```

开发预览：`http://127.0.0.1:5192/`。工具链预览使用隔离内存，不提供完整的真实文件服务；项目目录流程使用 Mewvis 宿主或 `preview:packed` 验证，不回退到浏览器存储。

基础编辑能力与剩余缺口见[基础配置与编辑能力](docs/foundations.md)。各工作区的“内容目录”支持草稿查找、类型筛选、使用位置与依赖检查，并可跳转到具体编辑区域；目录检查不替代试玩就绪检查。

组合计分的创建、专属编辑与游戏窗口说明见[玩法框架](docs/frameworks.md)。

应用每次打开先进入项目库。没有用户项目时显示空态，内置示例不自动变成项目。创建时填写名称和父目录，默认“从零开始”，也可选择“从示例创建”；先选择游戏类型和玩法框架，示例只在当前类型中提供。按项目名新建独立文件夹，目录已存在则拒绝覆盖。创建成功后进入策划概览，项目库显示各自的文件路径；“打开项目”可以重新加入已有的项目目录。

`preview:packed` 使用生产沙盒桥接、数据服务、工作区登记、SQLite 和文件 SDK，在系统临时目录中验证；“选择”使用验收父目录，“打开项目”选择临时目录内的首个项目，目录选择器为验收替身。界面刷新会重新读取临时文件和索引；退出验收服务会清理临时目录。该服务与真实应用数据隔离；`?theme=dark` 检查深色主题。生产宿主使用真实目录选择器。

## 类型、框架与项目文件

`main/frameworks/catalog.ts` 定义游戏类型、玩法框架、模型格式、验证模拟器和支持范围；`compatibility.ts` 检查这些信息是否一致。组合计分使用独立 `gameplay-card-v1`，与经营复用数值结算基础；斗地主使用独立 `gameplay-doudizhu-v1` 与专属执行器；叙事使用独立模型和执行器。卡牌规则及从零建项步骤见[组合计分说明](docs/card-scoring.md)和[斗地主说明](docs/doudizhu.md)。一个玩法框架目前对应一个内置模拟器，不提供任意跨类型自动转换。

内置示例“多路径发展”和“组合计分”分别位于 `main/app/projects/templates/development.json` 和 `main/app/projects/templates/combination.json`，只在用户明确选择示例创建、应用或重置时复制内容。示例不会随项目编辑而变化，应用升级也不会自动覆盖项目规则。经营空白项目使用 `blankModel`，叙事使用 `blankNarrative`；组合计分框架使用 `createCardScoringModel`，准备必要计分结构及空牌库，不插入示例卡牌。纯类型建模仍可使用 `blankCardModel`。卡牌示例 JSON 直接使用独立卡牌结构，新建或明确重置时由框架注册补充组合声明，卡牌与规则内容保持示例定义。

`main/frameworks/numeric-runtime.ts` 登记 `resource-turns@1`（回合发展）和 `card-combination@2`（卡牌组合），分别提供兼容性检查、初始化和推进入口；公共事务结算复用纯引擎。模拟器通过定义引用执行规则，不读取示例来源。卡牌组合要求牌库与计分行动；回合发展拒绝卡牌规则，防止静默忽略。

```text
用户选择的父目录/
  项目名/
    models/
      core.json                  # 当前规则及项目元数据、命名版本
    configs/
      playtest.json              # 场景、用户策略及当前对照选择
    runs/
      run-标识.json               # 规则快照、种子、逐步决策、事件及最终状态
    experiments/
      experiment-标识.json        # 实验计划、规则快照与逐局样本
    backups/
      时间-规则标识.json           # 切换、重置之前保存的完整副本，按需创建
    .mewvis/workspace.json        # 宿主维护的目录登记
    workspace.db                 # 宿主维护的工作区数据库
```

`models/core.json` 的顶层字段是经营 `gameplay-model-v1`、卡牌 `gameplay-card-v1` 或叙事 `gameplay-narrative-v1` 模型，`project` 字段保存 `gameplay-project-v4` 元数据（项目 ID、游戏类型、玩法框架、可空示例来源、可空模拟器标识与版本、核心循环、待验证问题、创建时间、命名版本）。解析时分离元数据，运行时由模拟器检查并执行规则。只接受 v4 元数据和对应类型的当前模型，不推断或转换旧格式。规则与元数据在同一个文件中原子保存，模型可由外部编辑器修改。

宿主的 `application-data` 只保存 `gameplay-lab:library:v2` 项目索引（ID、登记工作区、名称和路径），不保存当前规则和命名版本。打开项目会重新读取 JSON；自动保存携带文件修改时间，外部变更后拒绝覆盖，可在项目设置确认后重新读取。

项目设置支持修改名称、查看目录与规则文件、选择当前类型的玩法框架、应用同类示例及重置当前示例。框架选择保留内容，不兼容项在概览提示。应用与重置示例需要确认，先备份当前 JSON 到 `backups/`，再替换规则并选择示例配套的模拟器；项目身份、名称、核心循环、待验证问题和命名版本保留，已经开始的运行继续使用原快照。

应用只读取当前格式，不提供旧格式解析、迁移或升级入口。加载遇到不兼容的项目、命名版本、记录或数据库数据时提示并保留原件，不自动删除或裁剪版本，也不扫描清理备份。用户选择“查看并删除”后，确认框显示路径、原因和删除范围；取消不修改数据。确认删除项目会移除整个项目目录、工作区登记与索引；确认删除记录只移除选中的文件。删除前重新核对文件与读取快照，外部修改后需重新加载并再次确认。

对局写入 `runs/*.json`，对照实验写入 `experiments/*.json`，不再按页面会话截断保留数量。对局每次决策、实验每局样本完成后原子保存，保存失败不会把未写入的结果显示为已完成。重新打开项目后可继续未结束的对局，查看事件并逐步回放；取消或中断实验可继续剩余样本，已完成的策略/种子单元不会重复运行。

记录带有引擎版本、完整规则快照、种子、参与者数、决策及事件，并保存最终状态。对局还记录每步由手动还是哪个内置策略驱动。策略对照保存一份共享规则；版本与参数对照保存基准和各候选规则，各样本分别保留分组标识、决策、事件、结果和异常。读取时用固定规则重算并核对事件与最终状态，不依赖当前草稿。不兼容、损坏或未知版本的记录会被单独提示并保留原文件，用户确认后才可删除选中的文件；外部改动需点击“重新加载记录”后再继续，旧页面不能覆盖。单个记录上限 16 MiB。

## 文字冒险

`main/frameworks/branching-story/` 分别维护独立的剧情模型、校验器、执行器、记录与页面；`Workspace.tsx` 协调人物、剧情/选项、状态变量、手动试玩、结构检查、记录及命名版本。没有数值行动、回合和阈值目标要求。

- 人物可以担任发言者；剧情包含正文、选项和结局标记。
- 变量支持布尔、整数和文本，条件全部满足才可选择；后果支持类型匹配的赋值或数字加减，按顺序原子提交。
- 每个选项明确目标剧情；结局不能带被忽略的选项，引用中的定义需要先解除引用再删除。
- 无可用选项显示条件死路，200次选择上限单独标记，不误报为结局。
- `gameplay-story-run-v1` 冻结人物、剧情、变量、条件、后果及模拟器版本，保存每次选择和最终状态；`main/frameworks/branching-story/repository.ts` 通过生产 SDK 保存并重算验证。
- 报告提供连线结构可达性，不穷举变量条件，也不代表叙事体验质量。没有套用数值玩法的胜率实验界面。

策划及叙事记录各限4MiB，超过时拒绝写入并保留原文件。命名版本最多10个，保存整份类型专属模型。

## 数值玩法：场景、策略与配置快照

`configs/playtest.json` 使用 `gameplay-playtest-v1`，保存项目标识、最多 20 个场景、20 个自定义策略、当前场景与最多 4 个对照策略。三种内置决策策略由系统提供，在复制或创建运行快照时深拷贝，不会因项目编辑而变化。缺少配置文件时准备基础场景，进入项目后按普通自动保存写入；不会因此创建新的项目。

配置通过 SDK 原子写入，保存前核对已读取的内容与修改时间；外部修改需点击“重新加载配置”。格式损坏时保留原文件并禁用新运行。切换项目及启动运行前会保存当前配置。应用/重置示例保留配置，失效的定义引用会提示修复，不会静默删除用户策略。删除定义时同时检查场景覆盖、策略条件、成本保留门槛和行动引用。

新建的对局、实验使用 `gameplay-run-v3` / `gameplay-experiment-v4`，冻结模拟器标识与版本、规则、场景及使用的策略配置；每位参与者使用对应策略，历史回放从冻结的各自初始状态重建。修改当前配置不会影响已开始的对局或中断实验。只读取这两个当前格式；其他格式提示并保留，不会在加载时自动清理。

## 数值玩法：版本与参数对照

在“实验记录”展开“版本与参数对照”：

1. 保存一个命名版本，修改草稿后，选择基准和候选来源；也可比较两个命名版本。
2. 单参数扫描选择基准规则、行动成本/数值收益或系数/同类奖励/目标门槛/流程参数，设置整数起点、终点与正步长。最多扫描 11 个点，始终保留原值基准；原值落在范围内时复用基准，避免重复。
3. 使用当前选定的场景、策略组合和种子范围运行。开局数值及能力由基准解析后固定，因此模型初始值的差异不参与本次开局；卡池和流程按分组规则执行。状态与能力标识必须一致，各组都要通过模拟器兼容性、策略和场景引用校验，模拟器标识和版本必须一致。

规则对照采用 `gameplay-experiment-v4`，保存在原有 `experiments/` 目录；包含基准、候选或参数分组的模型快照，沿用逐局保存、取消、重启恢复、续跑和样本回放。总预算最多 240 局，单文件仍受 16 MiB 上限约束；扫描不修改当前模型、命名版本或内置模板。

报告展示各分组和策略的达标率、平均步数、截断和异常，以及各参与者、各目标的结果与规则差异。差值只使用同策略、同种子且双方均正常完成的配对样本；平均步数包括目标结束与预算截断，异常样本不计入均值，未形成配对时显示空值。参数扫描同时提供平均步数 / 各玩家达标率趋势图。达标率差使用百分点，不将小样本差异解释为显著改进。

## 数值玩法的其他操作

- 项目库首页采用紧凑列表，集中展示项目名、说明与行动和目标数量。页标题、项目名、说明与统计分别为 18px、14px、13px 和 12px，桌面列表行最小 80px；窄屏将统计移到说明下方，项目内导航在进入项目后出现。
- 新项目先选类型与玩法框架，默认从零开始；卡牌和经营可分别复制对应示例，叙事当前只提供空白入口。
- “策划概览”编辑设计目标、核心循环、待验证问题与模拟器，列出结构、引用及兼容性问题并定位编辑入口。未完成的项目正常保存；规则就绪后，无须先配置自动玩家即可人工试玩。
- 关系图和定义列表共用模型；右侧修改成本、效果、前置能力、初始状态和目标。高级规则支持增加或移除成本、数值/能力/组合效果，配置数值来源、牌库、倍率与每对同类奖励。定义可复制、删除；删除前列出成本、目标、前置、效果及周期结算中的引用，存在引用时先解除。
- 卡牌的“卡牌与回合”分别编辑卡牌定义、牌库数量、手牌容量、开局抽牌、出牌上下限、补牌时机与弃牌回收；卡牌和牌库支持复制与引用保护删除。经营的“流程与产出”编辑行动次数、轮数与周期效果，卡牌也可使用这些数值基础。未完成的内容可保存草稿，运行前必须通过完整校验。
- 图中的连接由消耗、效果、前置与目标引用生成，不能随意画出没有执行语义的连接。
- 试运行冻结完整模型；可手动决策、样例策略单步、结束行动、查看事件和历史状态。数值玩法的规则检查与结算共用纯 TypeScript 引擎。
- 卡牌与经营模拟器复用公共数值结算。回合发展使用库存、周期产出与前置能力；卡牌组合使用独立定义、按数量生成的实体牌、牌区、出牌约束、同类奖励、固定或状态倍率及可配置抽补牌。新建组合效果采用固定倍率 1、配对奖励 0，无须创建倍率状态。
- 支持 1–2 位参与者、轮流行动、每阶段 1–10 次行动、最多 100 轮；200 步作为运行预算。目标在每次行动及周期结算后检查，同一检查点同时达成时保留共同结果。
- 场景支持命名、复制、删除、切换；保存 1–2 位参与者的名称、各自状态/能力覆盖、自动决策策略及 1–12 个连续种子的范围，未覆盖的初始条件继承模型。覆盖不会修改模型规则。
- 三种内置决策策略只读，可复制为项目内的自定义策略。表单配置行动规则、优先级或随机权重、全部满足的状态条件、支付后资源保留门槛和组合选牌方式；无匹配规则时使用基础策略或结束阶段。优先级/权重为 0 时停用该行动，条件不满足的已配置行动不会被回退策略选中。策略门槛只影响自动决策，手动行动仍由模型规则校验。
- 对照实验选择 1–4 个策略，逐一替换场景中第一位参与者的策略；双人时另一位参与者保持固定策略。各组使用相同初始配置和种子范围，报告完成、任一玩家达标、截断、异常、平均步数，以及每位参与者和各目标的达成局数。固定先手顺序，未做位置交换；缺少随机机制时会重复相同局面，不据此宣称平衡或有趣。
- 草稿自动保存，未完成的草稿可保留；试运行和命名版本需要通过完整校验。版本同时冻结模拟器与设计说明，最多 10 个；复制回草稿恢复对应配置，不会覆盖原版本。

## 执行与数据边界

`main/domains/card/model.ts` 与 `main/domains/card/validation.ts` 定义独立卡牌规则，`main/domains/turn/model.ts` 定义共享数值结构，`main/domains/turn/validation.ts` 校验经营 `gameplay-model-v1`；`main/domains/turn/engine.ts` 执行纯状态转移，先复制再整体提交，非法选择、资源不足或数值越界不会留下部分支付。回放依据固定模型、种子与动作，测试覆盖补充集合时的确定性和对象守恒。

首版状态使用有界非负整数，效果支持数值增加、授予能力与已登记的组合计分。目标为阈值条件，可配置多个目标；尚未实现相对领先、持续倒计时、任意表达式、通用实体组件编辑、自由机制模块加载或同时行动。集合内容和配对奖励可编辑；计分仍限于基础值、同组配对奖励与固定或状态倍率这一机制，未提供任意公式或新的计分机制编程。

策略支持内置样例与表单配置，没有外部脚本、LLM 调用或通用策略编程界面。AI 按钮替换为实际可用的使用指南。载体设计、正式游戏生成与完整文明策略规则属于后续迭代。

棋盘经济、塔防、完整卡牌对象/牌区与触发、构筑商店及更丰富的叙事机制按 [调整规划](docs/roadmap.md) 后续批次实现。

首版面向单页面编辑，尚未实现多窗口变更合并。真实宿主的持久化行为需在 Mewvis 中启用应用后验证；独立预览只验证 SDK 适配下的工作流程。

本地设计证据与验收记录见 `design-qa.md` 和 `qa/`；目录流程验收位于 `output/gameplay-lab/project-flow-qa/`，规则编辑与记录持久化验收位于 `output/gameplay-lab/rules-history-qa/`，场景与策略配置验收位于 `output/gameplay-lab/playtest-config-qa/`，版本与参数对照验收位于 `output/gameplay-lab/comparison-qa/`。从零建项与模拟器验收位于 `output/gameplay-lab/blank-project-qa/`。类型化与从零叙事验收位于 `output/gameplay-lab/typed-design-qa/`。这些探索与验收产物独立保留。

斗地主提供三人叫分、十四种牌型配置、手动出牌、基础自动对手、阵营结算、规则版本及冻结对局回放。经典斗地主、英雄斗地主预设与用户自定义组合共用骨架、模块和布局装配流程；在“玩法组合”管理兼容模块，侧栏与牌桌按启用项装配。详见[玩法组合与模块接入](docs/composition.md)。组合计分也已接入相同协议，基础计分和配对计分预设共用运行与界面装配。关闭配对奖励会同步影响自动选牌、预估与结算；金额保留，对局与实验冻结组合和模块状态。资源发展和叙事仍使用已有入口，斗地主批量实验尚未提供。
