# Tavern Prompt Quality Evaluation

本评估用于优化酒馆输出模式和风格套餐。真实模型输出报告默认写入
`apps/desktop/tmp/tavern-prompt-quality-eval.json`，该目录不提交。

## 评估方法

1. 硬指标评分
   - XML 合同是否使用 canonical tag，解析后是否无协议残留。
   - 是否贴合 dialogue-chat、novel-prose、third-person-prose 的呈现形态。
   - 是否承接场景目标和关键线索。
   - 是否保持角色边界，不替用户做选择，不写其他角色未公开心理。
   - 是否有具体动作/环境细节，避免空泛氛围和模板句。

2. SPEED 模型内容裁判
   - 使用 `SPEED_MODEL_IDS` 中可用模型评估最终可见片段。
   - 评估重点不是 XML，而是小说模式是否连成小说、对话模式是否像真人现场回应、环境描写是否服务剧情。

3. 真实酒馆场景评估
   - 使用导演调度、角色 Agent、多角色发言、旁白/环境承接和续调度模拟正常酒馆流程。
   - 每个测试至少 4 轮用户输入，累计模型可见输出至少 1000 字，再判断整段是否能作为网文片段存在。
   - 额外统计段落结构：段落数、平均段长、最长段落、超过 180 字的大段落数量。

4. Codex 人工复核
   - 我会阅读最终可见片段并给出人工分，作为套餐排序的重要依据。
   - 人工复核更重视阅读体验、角色真人感、环境比例、互动空间和“是否像 AI 在总结”。

## 网文场景复核

这轮不再使用单次 1000 字输出作为主要依据，而是模拟正常酒馆：用户连续推进，导演每轮根据场景目标、现场压力、角色动机和待回应事项调度旁白与多角色。达到至少 4 轮、累计模型可见输出 1000 字后，再判断整段能否作为网文存在。

| ---------- | --------------------------: | --------------------: | --------------------------- | -----------: | ------------------------------------------------------------------------------------ |
| 起点长篇   | 均分 0.79，2/3 有效裁判通过 | 生成 4 轮，均 1865 字 | 最长约 73 字，超 180 字为 0 |           76 | 段落和调度可读，已接近章节开头；严格判断下仍停在单场问询，长线势力和主线钩不足。     |
| 番茄快节奏 |     均分 0.72，2/4 裁判通过 | 生成 4 轮，均 1449 字 | 最长约 89 字，超 180 字为 0 |           72 | 短段落和外部压力改善，但仍容易像室内调查纪要；需要更强事件打断、即时后果和爆点反馈。 |

人工判断：两套新增套餐还不能宣称稳定达标。它们比原始小说模式更接近网文，尤其段落结构已经明显改善，但“多轮之后能不能自然连成一章”仍取决于导演是否持续制造公开压力，而不是只按用户点名进入问答链。

## 结论

- 默认推荐小说正文稳态、克制文学、镜头悬疑。
- 第三人称旁白可作为可选模式，但需要持续抑制直接对白和菜单式收尾。
- 对话模式优先推荐写实对话；轻快对话适合轻松场景，不适合严肃调查默认。
- 番茄/起点套餐可以作为网文方向的快速引用预设，但当前定位是“可继续打磨的网文基线”，不是最终最优解。
- 可以提高旁白占比，但旁白必须承担场景压力、线索状态、时间推进或未发言角色动作整合，不能只是纯氛围描写。
- 小说正文模式要求短段落：通常 40 到 120 个中文字符，尽量不要超过 180 字；动作、对白、环境变化和反应压力应拆段。
